# UI 设计规范

## 原则

| 原则 | 要求 |
| --- | --- |
| 信息优先 | 视觉层级服务于业务信息，不做无意义装饰与重复说明 |
| 页头克制 | 列表页页头只放标题与必要操作，不在标题下重复解释页面名称 |
| 一致分组 | 筛选、数据、详情、编辑统一使用卡片容器 |
| 单一主色 | 交互主色用蓝色；绿色只表达成功语义 |
| 复用优先 | 相同交互必须复用公共组件或全局样式，不复制页面级实现 |

`--color-surface-muted`，不用蓝色系底色。

## 界面外观（明 / 暗）

| 项 | 要求 |
| --- | --- |
| 档位 | 三档：`auto`（自动，跟随系统，默认）、`light`（浅色）、`dark`（深色）；档位存浏览器本地 `theme.mode`，不落库、不产生请求 |
| 入口 | 侧栏（移动端抽屉）左下角用户下拉里的「外观」二级菜单：鼠标悬浮父项「外观」，向右浮现自动 / 浅色 / 深色三档（下拉向上展开，子菜单空间不足时自动翻转），当前档勾选 |
| 解析 | `auto` 时用 `prefers-color-scheme` 实时判断；用户显式选择后固定该档，覆盖系统设置，刷新与换页都保持 |
| 落地 | 解析结果写到 `<html data-theme="light|dark">` 与 `color-scheme`；`styles.css` 的颜色令牌按该属性整套切换；Naive UI 组件由 `n-config-provider` 同时切到 `darkTheme` + 深色调色板覆盖 |
| 首屏 | `index.html` 在入口脚本前用同一规则预置 `data-theme`，避免刷新时先浅后深的闪烁；app 启动后再由 store 校正 |
| 不设快捷按钮 | 用户菜单之外不放独立的明暗切换图标，外观只从「外观」二级菜单切换（避免同一功能两个入口） |
| 新增样式 | 只引用上文令牌，不写死颜色；确需新颜色时先在设计令牌表里加一组浅 / 深值，再引用变量 |

小程序端**不提供手动档位**，直接使用 TDesign 官方主题文件 `miniprogram/theme.wxss`，靠 `prefers-color-scheme` 自动跟随设备深色模式：

| 项 | 要求 |
| --- | --- |
| 跟随方式 | `app.json` 保持 `darkmode: true` + `themeLocation: theme.json`；`theme.wxss` 的 `@media (prefers-color-scheme: light/dark)` 自动切换 `--td-*`。不写 storage、不提供「外观」入口、不注入 `themeClass` |
| 样式令牌 | `app.wxss` 第一行 `@import "theme.wxss";`；页面与组件只引用 `--app-*` 语义别名，别名全部指向官方 `--td-*`（如 `--app-bg: var(--td-bg-color-page)`、`--app-brand: var(--td-brand-color)`），因此颜色自动跟随系统 |
| 原生外观 | `theme.json` 的窗口底色与官方主题页面底色一致（浅色 `#f3f3f3` / 深色 `#181818`），状态栏与下拉区域由 `darkmode` 自动切换；导航栏由 `app-navbar` 内的 `t-navbar` 渲染 |
| 新增样式 | 页面与组件样式只引用 `--app-*` / `--td-*` 变量，不写颜色字面量，也不在页面里用 `@media (prefers-color-scheme)`；新增语义时先在 `app.wxss` 的 `page, .page` 别名块里映射到官方 `--td-*`（`npm run check` 在 `miniprogram/` 下校验） |

## 小程序页面约定

小程序与网页端共用同一套语义与文案（`utils/i18n.js` 的 `zh-CN` / `id-ID` 键集合必须一致），
交互控件按移动端实现：列表页统一「搜索 + 筛选面板 + 结果计数 + 状态面板」，登记与详情统一「卡片分组 + 底部主按钮」。

| 项 | 要求 |
| --- | --- |
| 导航栏 | 全站 `app.json` 设 `navigationStyle: custom`，每个页面首行引入共享 `components/app-navbar`（内部用 `t-navbar`）：`title` 取 `i18n` 文案；外观由官方主题自动跟随，不传主题类。列表页不再另写顶部大标题，页面名只出现一次；非首页默认显示返回箭头，无历史可返回时回首页 |
| 列表页骨架 | 根节点 `class="page-shell"`；页面首行 `app-navbar`，内容自上而下依次为 `<filter-panel>`（搜索 + 筛选）、结果计数、列表卡片、状态面板 |
| 导入时间 | 精简版二级库、华星总库存、物料编码库在列表顶部显示「导入时间：YYYY/MM/DD HH:mm（相对时间）」；数据取各页 `last-import` 接口，相对时间统一用 `utils/time.js` 的 `importTimeLabel`（超过 1 天保留小时，如「2天3时前」），非导入型页面不显示 |
| 列表卡片 | 统一 `24rpx` 内边距、`24rpx` 圆角、`2rpx` 边框、`0 10rpx 30rpx var(--app-shadow-color)` 阴影；卡片间距 `16rpx`。状态 tag 统一 `variant="light" size="small"`；非状态元信息（申购人、台账标签等）用 `theme="default"`，不抢状态色 |
| 详情页 | 列表卡片点击后 `navigateTo` 对应详情页（按 `id` 请求详情接口），**不再用详情弹窗**；详情页统一 `app-navbar` + 摘要卡 + 分组卡片，页面内不重复页面标题 |
| 搜索 | `t-search`（`shape="round"`、`confirm-type="search"`），只做「综合搜索」（跨字段 OR）；收起态**不放字段选择器**，组合搜索统一在面板里做，避免两个入口语义重叠 |
| 分字段搜索 | 指**多个字段组合搜索**（AND）：面板顶部「分字段搜索」区把该页每个字段都列成一个输入框，填哪几个就同时满足哪几个，留空的字段不参与过滤，与网页端「每字段一个输入框」完全一致。**每个字段都显式可见**，不允许做成「先选一个字段、再添加条件」的形式（那一次只能一个字段，不是组合搜索）。字段之间是 AND，字段内部沿用后端的包含匹配 |
| 筛选面板 | 统一用共享组件 `components/filter-panel`：收起态**只有一行**「搜索 + 筛选按钮」，点开是底部弹层，维度再多也不占首屏。分区由页面按 `{ key, title, kind, options }` 组装，`kind` 取 `single`（单选胶囊）/ `multi`（多选胶囊）/ `range`（数值上下限）/ `dateRange`（日期区间）；**胶囊类分区首项固定为「全部」（`value: ''`）**。点选项只改草稿，点「确定」一次性发 `change`；点「重置」**清空全部条件并立即生效**（同时收起面板，角标归零）。**收起态不再回显已选条件**（与搜索框并排的那行小胶囊是重复信息）：生效条件个数只体现在筛选按钮的角标上（"有内容"才算，空数组 / 空区间算 0），具体条件在面板里看、在面板里改 |
| 筛选项来源 | 固定枚举（库存状态、隐患状态 / 等级、仅逾期）在页面内置；自由文本（提报员工、子项号、类别、业务员、申购部门 / 申购人、隐患类型 / 责任单位、台账标签）来自对应 `filter-options` 接口。分享带来的值若已不在候选里必须补进选项，否则面板看不到「筛了什么」（`buildSection` 负责） |
| 选项加载失败 | **不弹打断式 toast**：列表本身是好的，弹「筛选选项加载失败」会让人以为整页坏了，而且弹完没有重试入口。做法是把 `optionsFailed` 传给面板，在弹层顶部显示一行「筛选项没加载出来 · 重新加载」（点整行触发 `retryoptions`，页面只重拉选项、不重新登录也不重查列表）。固定枚举分区不依赖接口，失败时照常可用 |
| 多选与区间 | 多选分区在请求里用 `\|` 连接（后端按「任一」匹配）；区间在请求里拆成 `from` / `to` 两个参数，空的那一端不发。日期区间用 `t-date-time-picker`（`mode="date"`），不做手输 |
| 项目切换 | 首页「个人信息」弹窗的「当前项目」行用 `t-picker` + `t-picker-item`（选项按组件的 `label` / `value` 契约传入，`value` 属性传 `[当前项目 id]` 以定位当前项），取消不改动、确认才切换；按钮文案走 `utils/i18n.js` 的 `cancel` / `confirm`，不沿用组件库的 zh_CN 词典。`t-picker` 从 `t-popup` 内打开，需用 `popup-props` 抬高面板与遮罩层级 |
| 主操作 | 列表页的登记/新增入口用 `t-fab` 悬浮圆钮，只在有写权限时渲染（见 `utils/features.js`） |
| 状态面板 | 加载中用 `t-loading`，无数据用 `t-empty`；「本来为空」与「筛选后为空」用不同文案，避免误导（页面维护 `filtered` 标志） |
| 反馈 | 轻提示用 `Toast({ context: this, selector: '#页面-toast' })`，需要提示的页面在 WXML 里放一个对应 id 的 `t-toast`（纯静态提示页如「停用」「注册已关闭」除外） |
| 只读档位 | `query_only` / `disabled` 档位下不渲染写入口（FAB、上传、提交按钮），页面仍能完整展示数据 |

### 小程序首页

| 项 | 要求 |
| --- | --- |
| 入口顺序 | 页面首行 `app-navbar`（标题「首页」，不显示返回箭头）；内容自上而下：品牌头图（品牌名、车间说明、用户徽章、扫码主操作）、`功能入口` 标签、功能卡片网格 |
| 品牌头图 | 深色渐变实底 + 轨道装饰（与绑定页的品牌面板同一套语言），标题下常驻一行车间说明；用户徽章用玻璃底放在头图右上角，点击打开个人信息弹窗 |
| 扫码出库 | 头图内的玻璃卡，整张卡片可点（`bind:tap="scanMaterial"`），**不嵌套「开始扫码」按钮**；白色图标方片 + 标题 / 说明 + 圆形描边箭头。`canScan`（`canOutbound()`）为假（精简模式或库存只读 / 禁用）时不渲染 |
| 功能入口 | 两列等宽紧凑卡：图标与标题同一行（图标落在标题基线上），说明在下方；**所有入口平级**，同一套版式与配色，只按功能开关决定显隐；入口按功能开关过滤，等登录态与功能配置都返回后一次性渲染（`featureReady`），避免先全显再收起；入口数为奇数时最后一张**靠左排列**，不居中 |
| 分享按钮 | 固定在**左下角**的圆形按钮（`open-type="share"`），与列表页「返回顶部」FAB 同一位置与尺寸；页面底部预留 FAB 高度，避免滚到底时压住最后一行入口 |



## 页面结构

### 页头

```html
<div class="page-header">
  <div>
    <h1 class="page-title">页面标题</h1>
  </div>
  <div class="page-actions">
    <n-space>页面操作</n-space>
  </div>
</div>
```

| 场景 | 要求 |
| --- | --- |
| 列表页 | 不使用 `page-subtitle` |
| 详情弹窗 | 标题下可显示一行关键元数据（编号、状态、时间、型号），最多一行 |
| 标题右侧时间 | 详情弹窗的「最后更新时间」放 `#header-extra` 槽（标题右侧、关闭按钮左侧），用 `.card-header-time`（12px，比正文小一档、比标题 16px 明显轻），**只显示时间、不带「最后更新：」前缀**；不占页脚空间、不与页脚操作按钮抢位。到关闭按钮之间要留出间距：组件库只给关闭按钮 8px 左外边距，12px 的时间会贴上去，`.card-header-time` 再补 `margin-right: 8px`（合计 16px）。窄屏放不下时标题换行即可，不要 `nowrap`（会把标题挤出可视区） |
| 业务规则 | 放进对应卡片、表单提示或 `n-alert`，不写在页头 |
| 操作区容器 | 页头右侧控件统一放进 `.page-actions`（不直接与标题同级），便于窄屏统一压缩；隐藏的 `file input` 随按钮放在容器内即可 |
| 移动端标题 | 移动端由布局顶部的窄导航条（菜单按钮 + 当前页标题）展示页面名，内容区隐藏 `.page-title`，只留操作区；桌面端无顶栏，内容区标题保持展示 |
| 移动端操作区 | 页头多个按钮必须排在同一行：`styles.css` 里统一把 `.page-actions` 内按钮字号压到 13px、内边距收窄，按钮组按内容宽度不压缩，超出时由操作区**横向滑动**承接，不换行、不把页面撑宽。滑动要能真正滑到每个按钮，靠两条互相配合的声明：`.page-actions` 的 `justify-content` 必须是 `flex-start`（写成 `flex-end` 会把溢出堆在左端，而横向滚动只能滚到右端，左端按钮永久不可达 —— 实测 320~480px 下「导出」「批量修改」被切在屏幕外），行内 `.n-space` 需 `width: max-content` 撑出可滚动区间（只设 `flex: none` 时会被压到容器宽度、`scrollWidth === clientWidth` 而滑不动）。由 `web/src/views/buttonRowScroll.spec.ts` 守住 |

### 页面标题与浏览器标题

| 项 | 要求 |
| --- | --- |
| 页面标题 | 桌面端由各视图的 `.page-header` + `.page-title` 承担（无顶栏，页面名只出现一次）；移动端由布局窄导航条展示当前页标题，内容区标题隐藏 |
| 浏览器标题 | 由路由 `meta.title` + `meta.parent` 拼成「上级 / 当前 - HXNI 电气无忧」；顶级条目（工作台、备忘录、二级库、华星总库存）不设 `meta.parent`，只展示当前页名，不挂「备件管理」这类根名称 |
| 上级取值 | 二级条目用所属菜单分组名（二级库 / 申购管理 / 隐患管理 / 台账管理 / 工作管理 / 系统管理），操作页用所属列表页标题或所属入口标题；详情已改为列表页弹窗，因此不再为详情单独设 `meta.parent` |

### 横向树（`vue3-tree-org`，至多三级）

有父子层级、且层级要在页面上看得见的数据用该组件呈现为横向树：**父节点在左、子节点在同一水平带上向右展开**，父子连线由组件自带的 CSS 伪元素绘制，页面**不自绘 SVG 或边框**。目前两处使用：隐患类型（一行一个「大类 + 小类」组合）与台账标签（真父子层级，至多 3 层）。

| 项 | 要求 |
| --- | --- |
| 触发条件 | 数据确实是父子结构（两级起、至多三级）且层级要在页面上可见时使用；纵向缩进场景用 `n-tree`，不要用它 |
| 数据 | 传**新建对象**（如 `buildHazardTypeTree()` / `buildLedgerTagTree()` 的产物），不要把接口列表直接传入——组件会往节点写 `$` 前缀字段 |
| 共享类名 | 容器统一挂 `.org-tree-horizontal`（`web/src/styles.css` 的「横向树（vue3-tree-org）」段）：隐患类型页与台账标签页共用同一段样式，页面只再挂自己的层级 class（如 `.hazard-type-tree`、`.ledger-tag-tree`），不另写一套 |
| 必需属性 | `horizontal`、`collapsable`；同时关闭 `draggable` / `scalable` / `node-draggable` / `tool-bar`，并传 `:define-menus="[]"` 关掉右键菜单，避免出现「新增/删除节点」等与业务无关的入口 |
| 根节点 | 组件要求单个根对象。多个顶层分组时用一层无标签虚拟根承载，并在样式里隐藏该根（空标签节点带 `is-empty`） |
| 操作范围 | 看数据模型：隐患类型只有**叶子**是业务实体行，分组不提供整组改名/删除；台账标签每个节点都是实体（都可改名称 / 备注 / 图片 / 上级标签），删除受「有子标签或被台账记录引用」保护 |
| 节点悬停浮层 | 节点上还有备注、图片这类一屏放不下的信息时，用 `n-popover`（`trigger="hover"`）承载：浮层只读，展示备注与图片缩略图；两者都没有的节点不弹浮层 |
| 层级上限 | 层级有上限时（台账标签至多 3 层），到第 3 层的节点不再提供「新增子标签」入口；前端隐藏只是体验，上限由服务端一并校验 |
| 层级不分主次 | 同一棵树里的节点样式一致（同字号、同字重、同内边距）：层级由连线与缩进表达，**不用字号 / 字重 / 卡片大小区分层级**；要补充的信息用数字计数（如台账标签的「3」表示 3 条台账使用该标签，含义放 tooltip）或中性小字，不用彩色标签堆在节点里 |
| 节点操作入口 | 节点上的操作（如台账标签的「新增子标签」）用图标按钮 + tooltip 说明，不用整词按钮；入口只在未达上限且有写权限时渲染，默认透明、悬停节点才显现，因此点击处理要忽略落在该按钮上的点击（`closest('.ledger-tag-node__add')`），否则点按钮会连带触发节点自身的编辑 |
| 样式 | 组件自带布局面向「可拖拽组织图」（外框白底、内容层绝对定位、内层 `height:100%`），放进卡片会高度塌陷且深色档露白底。`web/src/styles.css` 的「横向树（vue3-tree-org）」段已统一还原为文档流并映射 `--color-*` 令牌；新页面复用同一段（挂 `.org-tree-horizontal`），不要另写一套 |
| 溢出 | 容器设 `overflow: auto`；树比卡片宽时容器内横向滚动，页面整体不出现横向滚动条 |

### 半日时间线网格（`WorkTimelineGrid.vue`）

工作管理模块的任务视图与人员视图共用同一个时间线组件：**一行一个任务 / 一个人**，右侧按天铺开，
每天再分成「上午 / 下午」两个半天格——色块按起止的半天档精确跨列，所以「干到某天上午」这种
边界不需要另外用文字表达。

| 项 | 要求 |
| --- | --- |
| 结构 | 每行一个 CSS 网格：最左是**粘性名称列**（`position: sticky; left: 0`）＋每个半天一列（24px）；表头两行——第一行日期 + 星期（跨当天的两个半天列），第二行「上 / 下」 |
| 泳道 | 同一行同一天可能有多个活（一人一天干多个活、一个活多人分时段），因此色块按泳道分层：贪婪打包，最多 3 层，放不下的只计数并在名称列显示「+N」（tooltip 说明还有几条没画出来）；行高随层数增长 |
| 色板 | 用 `--color-work-bar-0..5-bg` / `-fg` 六组令牌（`utils/work.ts` 的 `workBarPaletteIndex` / `workBarHash` 取模，同一任务 / 同一姓名颜色稳定），明暗两档同名同义，不在页面里写死颜色 |
| 底色 | 周末与今天用弱底色（`--color-surface-muted` / `--color-primary-soft`）标记；每天边界用 1px 弱边框勾出 |
| 文字 | 色块上写「对方视角」的信息：任务视图写参与人员、人员视图写任务名；宽度不够时省略号，完整信息（任务 / 时间段 / 参与人员）放 `n-tooltip` |
| 交互 | 点色块打开工作记录弹窗（无写权限时为只读详情）；行尾插槽放行级操作（编辑任务 / 排活），只在有写权限时渲染 |
| 溢出 | 网格比卡片宽时容器内横向滚动，**页面整体不出现横向滚动条**；Shift + 滚轮横向滚动由组件自己处理（`n-data-table` 的滚动容器钩子不适用于自绘网格） |
| 空态 | 无数据用 `n-empty`；加载中用 `LoadingMask`（宿主 `position: relative`） |

### 工作台（`DashboardView.vue`）

工作台是「今天要处理什么」的入口，不是报表：每个数字都能点进对应列表，且列表已带好筛选条件。

| 项 | 要求 |
| --- | --- |
| 指标分组 | 按业务模块分卡片（二级库 / 申购 / 隐患），每卡 2×2 指标格，右上角「进入」跳模块首页；分组与指标跟随模块读权限位与二级库精简模式（精简模式只保留物资数） |

| 失败与刷新 | 各块（概览、隐患统计、低库存、最近出入库）独立请求、独立失败：失败的块显示「—」并在顶部提示「重试」，不拖垮整页；页头显示「更新于 HH:mm」；页面重新可见且数据超过 2 分钟时静默刷新一次（不遮罩） |
| 加载态 | 指标用骨架屏占位，不用整页遮罩 |

有写权限时弹窗内直接编辑，与列表的「新建」共用同一套表单；无写权限时字段禁用、页脚只留「取消」
（保存与页级操作都按写权限隐藏，`canWrite` 同时传给表单与图片/选择类子组件）。

| 项 | 要求 |
| --- | --- |
| 形态 | `n-modal preset="card"`，宽度与同类弹窗一致；移动端自动获得「移动端弹窗」一节的全局规则，页面不写断点 |
| 分组 | 内容多时用 `n-divider` 分节（“单据信息”“物资明细”），标题用业务名词，不用“基本信息 1” |
| 布局 | 两列用 `form-grid` |
| 页脚 | 左侧放页级操作（删除、转入申购记录、恢复为计划、反向冲销、在新页面打开）与只读摘要（最后更新时间、状态标签）；右侧放「取消 / 保存修改」，只保留一个主按钮 |
| 互转跳转 | 单条「申购计划 → 申购记录」与「申购记录 → 申购计划」都从详情弹窗发起，成功后跳对方列表并带上 `?detail=<新记录 / 新计划的 id>`，由对方列表自动打开详情弹窗（不再跳详情页） |
| 字段保存 | 关联物资、选择单位等随整表保存，不为单个字段加独立保存或确认流程 |
| 破坏性操作 | 不得与主要保存按钮同视觉权重 |
| 遮罩关闭 | **点击弹窗外部即可关闭**。因此详情弹窗必须写 `:mask-closable="false"` + `:close-on-esc="false"`（组件库的这两个开关会直接改 `show`、绕过确认），再由 `@mask-click` / `@esc` / `@close` 统一调用 `useMaskCloseGuard`：无未保存修改时直接关，有修改时弹「放弃修改 / 继续编辑」二次确认。`@close` 的处理函数必须返回 `false`（否则组件库会抢先关闭，拦不住误触）。只读看详情时脏判定应为 `false`，点遮罩直接关 |
| 直达链接 | 打开时把 id 写进列表页 URL 的 `?detail=<id>`，刷新 / 收藏 / Ctrl+点击新标签都能直接回到该弹窗；关闭时清掉该参数。列表页需在 `usePagedTable` 的 `urlSync.preservedQueryKeys` 里声明 `'detail'`，否则翻页 / 筛选会把它冲掉 |
| keepAlive 隔离 | URL → 弹窗的 watcher 必须判 `route.name` 是不是自己这条路由再处理：`keepAlive` 列表页跳走时只是被停用、watcher 仍会跑，否则会拿对方的 id 查自己的数据，并把对方刚写进的 `?detail=` 改写成自己的 id（申购计划 ⇄ 申购记录这两页最容易踩） |
| 旧链接兼容 | 原来的 4 条详情路径保留为 `redirect` 到对应列表页 + `?detail=<id>`，老链接不会 404 |
| 接线守卫 | 以上关闭接线由 `web/src/views/detailModalClose.spec.ts` 扫源码守住（含「详情弹窗清单与 `data-detail-modal` 标记一一对应」「必须禁用组件库自身的遮罩/ESC 关闭」「三条路径都转发 requestClose」「@close 返回 false」「不再引用已移除的详情路由」）；**新增详情弹窗必须同步接线并把文件加进该 spec 的清单**，否则漏接会静默失效。申购计划 ⇄ 申购记录的单条互转（按钮、接口入参、跳转、无写权限只读）由 `web/src/views/procurement/purchaseConvertFromDetailModal.spec.ts` 守住；工作记录详情弹窗的关闭行为由 `web/src/components/WorkRecordFormModal.spec.ts` 守住 |

> 历史：详情页曾用 `detail-toolbar`（返回入口）与 `detail-grid`（主信息 + 侧栏）两个全局类，
> 现已随详情页一并删除；不要在新代码里引用这两个类名。

### 移动端弹窗

`preset="card"` 弹窗在**窄屏或矮视口**（`(max-width: 768px), (max-height: 560px)`）由 `styles.css` 一段带标记的全局规则统一决定，**页面不写断点、不加局部样式**：

| 项 | 要求 |
| --- | --- |
| 四周留白 | 弹窗外框与视口之间留出余地：左右固定 `18px`，上下**最多 `72px`**（`padding: var(--dialog-pad-y) 18px`） |
| 上下留白自适应 | 上下留白取 `min(72px, (视口高 - 260px) / 2)`：默认为 72px，只在视口压到 404px 以下才收窄，保证弹窗始终有 260px 可用高度（否则页脚会被挤出卡片、按钮直接看不见） |
| 整窗限高 | 弹窗最高 `calc(var(--dialog-avail) - var(--dialog-pad-y) * 2)`（`--dialog-avail` 为 `100dvh`，`100vh` 作回退）——**与留白同源**，卡片 + 上下留白正好铺满视口，页脚不会跑到屏幕外 |
| 命中条件 | 必须同时匹配**宽与高**：手机横屏（如 844×390）宽度 > 768px，只按 `max-width` 判断会让整套规则失效、弹窗（416px）比视口（390px）还高 |
| 内部滑动 | 只保留**一层**滚动，由内容区（`.n-card-content`）承担；`n-scrollbar` 的行内 `max-height` 与隐患弹窗 `.modal-body` 的上限在这里让位；标题行与页脚 `flex: none` 保持自然高度（否则限高后页脚被压扁、按钮溢出卡片下沿），收缩量全部由内容区承担 |
| 底部按钮 | 底下一排按钮必须排成**一行**：按内容宽度不换行，并缩小尺寸与字号——≤768px 用 `28px` 高 / `12px` 字，≤360px 再压到 `26px` 高 / `11px`；极窄时由页脚横向滑动承接（与 `.page-actions` 同一约定） |
| 页脚间距 | 页脚 `padding-top` 为 `14px`：按钮与上方内容之间留出间距，不紧贴内容区。≤360px 只收窄左右（`padding: 14px 8px 8px`），**上边距必须保持同值**——写成 `padding: 0 8px 8px` 会把按钮上方的间距静默清零 |
| 宽度收缩 | 弹窗卡片 `min-width: 0`：部分弹窗写死了 `width: min(960px, 92vw)` / `calc(100vw - 32px)`，窄屏上可能比「视口减左右留白」还宽，flex 默认 `min-width: auto` 又拒绝收缩，会让左右留白一侧大一侧小 |
| 影响范围 | 只作用于 Naive 生成的 `.n-card.n-modal`；`.n-dialog`（确认弹窗）与 `n-image` 预览不匹配该作用域，不受影响 |
| 桌面端 | 不命中该断点时保持原有观感与 `70vh / 65vh` 滚动上限 |

弹窗底部按钮组仍用 `n-space` / `.modal-footer` 组织，无需为移动端改动模板；新增弹窗只要沿用 `preset="card"` 即可自动获得上述行为。改动这段规则时 `web/src/views/mobileDialog.spec.ts` 会守住上述接线（含「留白必须自适应」「必须同时匹配宽高」「页脚不得参与收缩」三条回归）。

## 图片附件

统一使用 `web/src/components/ImageUploader.vue`，不得在页面内新增原生文件选择器或另一套上传卡片。

| 项 | 要求 |
| --- | --- |
| 表单标签 | 统一写“图片附件” |
| 格式与数量 | JPG、PNG、WebP；单张 ≤ 10 MB；默认最多 9 张。**界面不写小字说明**：格式由文件选择框的 `accept="image/jpeg,image/png,image/webp"` 限定（选择器只列出这三种图片），超量与超大在选中后由 `validateImageSelection` / `validate` 拦截并提示 |
| 交互 | 点击选择与 `Ctrl+V` 粘贴；多选时最多 2 张同时上传，其余排队；**上传在途时添加入口照常可点**，可继续选图或粘贴（新文件进同一队列排队），不因已有在途请求而被挡住 |
| 上传反馈 | 每个文件一行独立状态与进度条（排队中 / 计算摘要 x% / 比对已有图片… / 上传中 x% / 失败可重试 / 可移除），慢网下不因单个文件失败中断其余。进度**最多显示到 99%**：请求体发完不代表服务端处理完，100% 只留给「该项从队列消失」的完成态 |
| 上传耗时 | 进度条下方同时显示「用时 x秒 / x分xx秒」，每秒刷新，让用户知道是慢还是在卡住。用时从**排到自己、真正开始处理**时起算，排队等待不计入；已失败项冻结显示本次耗时，重试后重新起算。数字用等宽（`font-variant-numeric: tabular-nums`）避免每秒抖动 |
| 保存联动 | 上传在途（含排队）时保存按钮必须禁用（`<n-button :disabled="…">`），避免 `image_ids` 漏掉还没传完的图；失败项是终态、不阻塞保存。同一表单有多个上传组件时各绑一个 `ref`，保存按钮按「任一为真即禁用」判断 |
| 免重复上传 | 超过 1 MB 的图片由组件自动先算摘要查重：命中且本地二次校验通过就直接复用，提示「已直接复用、免于重复上传」；查重失败静默降级为正常上传 |
| 删除确认 | 点删除按钮只弹二次确认弹窗（`useDialog`），确认后才调删除接口 |
| 组件职责 | 缩略图、删除按钮与二次确认、禁用态、上传队列与逐项进度由组件处理；不渲染格式 / 大小 / 数量的小字提示行 |
| 页面职责 | 用 `v-model:files` 绑定文件列表、`v-model:busy` 绑定保存禁用位，不自行拼预览地址或删除逻辑 |

```html
<n-form-item label="图片附件">
  <ImageUploader v-model:files="images" v-model:busy="imagesUploading" />
</n-form-item>
```

## 实现约束

| 项 | 位置 / 要求 |
| --- | --- |
| Naive UI 主题覆盖 | `web/src/theme.ts` |
| 跨页面布局与视觉类 | `web/src/styles.css` |
| 表格列宽令牌 | `web/src/constants/table.ts` |

| 颜色 | 优先用 CSS 变量或主题令牌，避免新增硬编码色值 |
